# AuToFishing

โครงการนี้พัฒนาแยกจาก repository เดิม `ggezname/autofish` ซึ่งใช้เป็นข้อมูลอ้างอิงแบบอ่านอย่างเดียว

## เวอร์ชันปัจจุบัน: v0.3.0 — ROI Vision Diagnostic

### ทำได้แล้ว
- ขอสิทธิ์จับภาพหน้าจอผ่าน AutoX.js
- อ่านความละเอียดภาพจริงจากอุปกรณ์
- ให้ผู้ใช้กำหนดกรอบสแกนด้วยพิกัด `x,y,width,height` (พิกัดพิกเซลของภาพจับหน้าจอ)
- ตัดภาพด้วย `images.clip` และประมวลผลเฉพาะ ROI เท่านั้น
- ตรวจจับแนวแถบสีแดงจากหลาย scanlines และรวมผลเพื่อลด false positive
- ตรวจหาแถบสีขาวในแนวเดียวกับแถบแดง
- แปลงตำแหน่งกลับเป็นพิกัดหน้าจอจริง
- ตรวจสอบขอบเขต ROI ก่อนยอมรับผลตรวจจับ
- สแกนต่อเนื่อง 20 วินาที พร้อมรายงานจำนวนเฟรม ความถี่ และเวลา capture/scan
- recycle ภาพหลังประมวลผล
- ไม่มีคำสั่งแตะหน้าจอเกมในรุ่นนี้

### วิธีทดสอบ
1. เปิด `main.js` ใน AutoX.js หรือใช้ GitHub Loader ที่โหลดไฟล์นี้
2. เปิดเกมและแสดงหน้าตกปลาที่มีแถบตกปลา
3. อนุญาตสิทธิ์จับภาพหน้าจอ
4. ดูขนาดหน้าจอที่สคริปต์รายงาน
5. กรอกกรอบ ROI เป็น `x,y,width,height` ให้ครอบคลุมแถบตกปลาทั้งแนว
6. ระบบจะสแกนภายในกรอบนั้นเป็นเวลา 20 วินาที
7. ดู Toast และ Log ของ AutoX.js: พิกัดแถบแดง/ขาว, จำนวนเฟรม, เวลาเฉลี่ยจับภาพและวิเคราะห์

ตัวอย่าง `180,620,520,100` เป็นเพียงตัวอย่างรูปแบบ ไม่ใช่พิกัดที่ใช้ได้กับทุกเครื่อง ต้องใช้พิกัดจริงจากภาพหน้าจอของอุปกรณ์นั้น

### ข้อจำกัดที่ต้องทราบ
- รุ่นนี้ยังให้กรอกพิกัด ROI ไม่ใช่ลากกรอบด้วยนิ้ว
- ตัวตรวจจับสีเป็น heuristic ตามเกณฑ์ RGB; ธีมเกม แสง เอฟเฟกต์ หรือสีที่ต่างกันอาจทำให้ตรวจไม่พบ/ตรวจผิด ต้องทดสอบจากภาพเกมจริง
- การตรวจจับสีขาวเป็นการค้นหากลุ่มพิกเซลสว่างในแนวเดียวกับแถบแดง ไม่ใช่การยืนยันความสำเร็จในการตกปลา
- ยังไม่มี tracking ความเร็ว/ทิศทาง, predictive timing, overlay ภาพสด, device profile หรือระบบ auto fishing
- ยังไม่ยืนยันความเข้ากันได้กับ Redfinger, Samsung, OPPO, Xiaomi, BlueStacks, LDPlayer หรือ MuMu จนกว่าจะทดสอบแยกอุปกรณ์

## Safety invariants
- ห้ามส่งคำสั่งแตะเกมใน diagnostic mode
- ห้ามรับตำแหน่งตรวจจับที่อยู่นอก ROI ของผู้ใช้
- หากขนาดหน้าจอเปลี่ยนระหว่างสแกน ให้หยุด
- ไม่ใช้ผลคาดการณ์เพื่อกดเกม
- ต้องทดสอบและเก็บผลจริงก่อนเปิดใช้งาน live automation

## ขั้นตอนถัดไป
1. UI ลากกรอบ ROI ด้วยนิ้วบนภาพ preview
2. วาด overlay ตำแหน่งแดง/ขาวและ confidence
3. เก็บ device profile และ calibration แยกอุปกรณ์
4. เพิ่ม tracker ความเร็ว/การกลับทิศและ anti-miss
5. ทดสอบชุดภาพหลายอุปกรณ์ ก่อน supervised live trials
